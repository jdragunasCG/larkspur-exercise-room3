The pitch

Six lines and a lever, from PITCH.md.

Built

A disruption-care agent for Larkspur that resolves cancellations, delays and diversions using APIs, MCPs and tools.

Does

Checks flights, searches for next available seats, resolves entitlements and escalates as needed.

Number

Caching the system prompt and tool list cut model cost at Larkspur's volume from $771/week to $293/week (13,700 chats/week) — a 62% reduction — measured on Stage 1's 5 ticket types, 3 runs each.

Safety check

check_policy and search_alternatives re-derive fare family, loyalty tier, and overnight status from the booking every call — never taken as arguments, so the model can't be talked into a wrong entitlement.

Next

Fix the abusive-message tone gap, validate with automated tests, then add tracing/observability (OpenTelemetry or similar).

Still broken

R8KD3F (abusive message) resolves calm and helpful with no tone gate at all right now. "Rebooks" is unverified past the offer stage in every trace run so far.

What this means at scale

Because the cache covers the fixed part of every request — the system prompt and tool list — the savings compound with volume rather than staying flat: the more contacts per week, the more turns hit the cache instead of paying full price. At Larkspur's current 13,700 chats/week that's already $771 → $293/week on Stage 1's easier ticket types.

We haven't yet measured whether the same 62% holds on harder Stage 2 cases, at concurrent load, or on live traffic — that's the next thing to prove, not something we're claiming today.

What's not proven yet

Tone. R8KD3F (an abusive message) still resolves calm and helpful with no tone gate at all — a separate, undone build goal, not touched by this lever.

Scope. This result is Stage 1 only (the 5 easier ticket types). Stage 2's harder cases haven't been benched against this change.

Loaded cost. $0.0214/contact is model cost only — Larkspur's fully loaded cost (infra, support, monitoring) hasn't been measured against it.
